## Требования к безопасности
1) Использование только защищенных каналов данных (https)
2) Контроль целостности сообщений с помощью механизма контрольных сумм (hmac)
3) Аудит (логирование) действий сотрудников и администраторов
4) End-to-end шифрование. Как на уровне транспорта так и на уровне приложения
5) Все операции на изменения данных должны быть идемпотентными. Должна быть реализована поддержка внешних ключей идемпотентности
6) Реализация полноценной RBAC ролевой модели. Корректность подтверждена тестированием
7) Токенизация чувствительных данных (номера телефонов и т.д)
8) Использование UUID в качестве идентификаторов для избежания раскрытия лишней информации
9) Соблюдение принципа Least Privilege

## Протоколы аутентификации и авторизации
1) Основной протокол аутентификации OpenID Connect (OIDC)
2) Использоватье MFA для доступа к интерфейсу сервиса
3) Реализация полноценной RBAC ролевой модели содержащей как минимум следующие роли
   4) Клиент - доступ только к своим данным
   5) Сотрудник тех поддержки - доступ ко всем данным на чтение (кроме защищенных)
   6) Эксперт - доступ ко всем данным на чтение (включая защищенные)
   7) Администратор - доступ на изменение любых данных

## Взаимодействие между системами предприятия и внешней платформой
1) Взаимодействие осуществялется по https
2) Для защиты канала используется установленеи двустороннего TLS-соединения с использованием доверенного удостоверяющего центра
3) Целостность сообщений контролируется на основании механизма Hmac c использованием заранее согласованного ключа 
4) Данные из внешней системы дублирутся в локальную БД. Применяется шифрование данных
5) Чувствительные данные передаются в систему вендора в виду токенов.
